## North-star fit

**Reuses before adding anything new:** FluidAudio 0.17.5's existing `AsrManager.transcribe(_:decoderState:language:)` script-aware token filter (`TokenLanguageFilter`, vendored at `Packages/CaptionCore/.build/checkouts/FluidAudio/Sources/FluidAudio/Shared/TokenLanguageFilter.swift`) — already in the pinned dependency, currently called from `ParakeetBackend.decode()` with `language: nil` (`Packages/CaptionCore/Sources/CaptionCore/ParakeetBackend.swift:221`). `CaptionEngineRouting.parakeetLanguages` (`EngineFallbackPolicy.swift:38`) is already the exact source of truth for which languages run on Parakeet, so it's the one place to map caption locale → FluidAudio `Language`. The evidence-gathering side reuses `SessionLog`/`replay.py score`/`check-saved-language.sh` + `gate-language`'s pattern (`docs/perf/whole-system-replay-results.md`'s "Regression case" section) rather than inventing a new harness. No new files beyond what each bullet of "What to build" names; no new abstractions.

**Simplest sufficient approach:** a locale→`Language` mapping function (reusing the 6-entry `parakeetLanguages` set) threaded through the three `ParakeetBackend` construction sites, plus two narrow instrumentation additions (decode-window bounds, commit point) surfaced the same way `onDecode` already is. No change to `TailCommitter`'s algorithm, `AdaptiveHop`, or line-splitting until evidence says one of them is the biggest source — guessing and rewriting that logic without evidence is very likely how the prior attempt burned 3 iterations and failed review.

**Where this spends vs. saves tokens:** spends a little now on instrumentation that has no payoff until it's run on real EdAcc audio (which this worktree doesn't have — see Decision 1); saves a lot later because every future accuracy ticket on this path reuses the same per-boundary breakdown instead of re-deriving it.

**Phone-OS direction:** neutral — an accuracy fix to the caption engine, not a new surface.

**More capable or more passive:** more capable — it's closing an accuracy gap between what the model can do and what the deaf primary user actually sees, with evidence that survives the next change (north star 3, the "quality is the product" test named in the ticket).

**Honest finding that changes scope:** I read FluidAudio's own `TdtDecoderV3.swift` comments (lines 639-641, 700): the `language:` hint only filters by **Unicode script** (Latin/Cyrillic/Greek). Every language Parakeet is routed for (en, es, fr, de, it, pt) is Latin-script, so this hint **cannot** distinguish English from Portuguese or Czech — it will not, by itself, fix the ticket's literal "yes" → "olha jestli" example (both are Latin). It's still worth doing (free, zero-risk, guards real cross-script drift, and is explicitly the "one suspect" the ticket asks to test), but I'm not claiming it closes the WER gap, and the plan below doesn't oversell it.
