**Simplest sufficient approach:** the owner picked **C (Folded)** with tap-to-reveal confirmed. Once there's only one look, `TranslatedCaptionLook` (CaptionCore, 4 cases) and the per-option branches in `TranslatedCaptionView` (today/bar/tag) have no reason to exist — collapsing them to the single chosen rendering is strictly less code, not a redesign. There is no new pure logic to add to CaptionCore: the fold state is a trivial `@State` toggle, and the "which line starts open" rule already differs legitimately across the three call sites (filtered-by-translated vs filtered-by-sound-label vs unconditional second-to-last), so forcing them into one shared CaptionCore function would be a false abstraction (Colton check) — I'm leaving each inline.

**Spends tokens on:** rebasing a 34-commit-stale branch and retaking screenshots; this is unavoidable because PR #255's branch (`mockup/246-translated-caption`) hasn't tracked `main` since Nov 2.

**Saves:** screenshot/flag combinatorics drop from 4 options × 3 devices × 2 themes (24) back down to 1 look × 3 devices × 2 themes (6) — the same count as the pre-#246 baseline.

**User impact:** more capable — removes two icons per caption line (translate mark, speaker mark) and lets the reader choose when to see the original, which is what the owner asked for after #238 made the screen "busy." No loss of information (ADR 0012 dim don't dismiss: what-was-said is one tap away, never gone).
