## North-star fit

**Reuses:** the already-built `TranslatedCaptionView` / `TranslatedCaptionLook.folded` rendering from the (unmerged) `mockup/246-translated-caption` branch (`Apps/Spike/Sources/TranslatedCaptionView.swift`, the `folded` case; `Apps/Spike/Sources/EarViews.swift`'s `EarSpeakingLine` for the "voice mid-word" firming logic it subsumes; `EarProgress.firmWords` in CaptionCore, unchanged) and the existing mock-up/screenshot-contract pattern (`CallPopupMockup`, `MarvinScreenshot`, `DemoMode` flags) rather than inventing a new one.

**Simplest sufficient approach:** the owner picked exactly one look (C, Folded) and confirmed its built-in tap-to-toggle is correct — there is no remaining variability. So instead of carrying the mock-up's `TranslatedCaptionLook` enum (4 cases, a flag parser, a language-tag helper for the unchosen "B" option) into production, this plan **deletes the enum** and hardwires `TranslatedCaptionView` to the one shipped layout. Carrying a selector type for a single, decided value is exactly the complexity Colton's check warns against. This mirrors how #233 shipped: the mock-up's unchosen options (ear button, pill) were deleted outright, not kept behind a flag.

**Where it saves/spends tokens:** no new CaptionCore type or tests are needed — `EarProgress.firmWords` already does the only piece of real logic (progressive word-reveal while speaking); "open/closed" is a plain SwiftUI `@State` toggle, not an algorithm, so adding a pure type for it would be the kind of thought-about-thought the Watts check flags. This also collapses three near-duplicate inline renderers (ContentView's translate-mark block, `EarSpeakingLine`, FaceToFaceView's translate-mark block) into one shared view used by iPhone, iPad split and the Mac pop-up — fewer lines to maintain going forward (compounding leverage).

**User impact:** removes two marks per translated line (the translate glyph + the always-visible "what was said" line) down to one glyph and an opt-in reveal, which is a real reduction in on-screen clutter — consistent with ADR 0013 (radical simplicity) and the owner's own stated reason for picking C. Nothing is hidden irrecoverably (tap re-reveals it), so this doesn't conflict with ADR 0012 (dim, don't dismiss) — it dims, it doesn't delete.
