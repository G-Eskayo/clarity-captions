## North-star fit

- **Reuses before adding anything new:** `CaptionLine.endTime`/the audio-clock concept `WordLagTracker` already uses for caption lag (`Packages/CaptionCore/Sources/CaptionCore/WordLagTracker.swift`); the `PercentileHistogram`/`Lag`-shaped stats pattern in `BetaFeedback.swift:78-123,442-447` (median/P95, now adding max via the existing `value(at:)` API — no new histogram math); `EarPhrases.take`'s existing `now` clock (`EarTranslation.swift:44`, `ProcessInfo.systemUptime` via `EarCenter.Self.now`); the existing closure-wiring pattern `CaptionModel.init()` already uses to connect `controller.onAudioLevel`/`onUpdate` into `BetaFeedbackCenter` (`ContentView.swift:123-142`); and `BetaFeedbackCenter.update(session) { ... }`'s existing fail-closed gate (`BetaFeedbackCenter.swift:109-113`), which production builds already can't reach — no new gating code needed for AC#3.
- **Simplest sufficient approach:** a new pure `EarDelayTracker` struct in CaptionCore, keyed by `CaptionLine.id` (already a stable, never-reused id per `CaptionStream`), fed three events (`phraseReady`, `translationReady`, `voiceStarted`) with plain `Double` timestamps on one clock. All three derived numbers (translate delay, voice start delay, behind-by) are simple subtractions/clamped-to-zero — no cross-clock bridging between the recognizer's audio clock and `ProcessInfo.systemUptime` is introduced; "end of the source phrase" is approximated as the uptime at which `EarPhrases.take()` recognizes the phrase (the same event caption lag is measured against), which is radically simpler and far less failure-prone than reconstructing a precise audio↔uptime calibration — I judge this the right trade for a beta diagnostic metric (noted as an approximation below, not a Decision — it has no visible product consequence).
- **Where it spends tokens/engineering, not saves:** a new ~40-line pure type + wiring in `EarCenter`, `BetaFeedback.swift`, `BetaFeedbackCenter.swift`, docs, and tests — proportionate to a three-new-measurement feature.
- **Phone-OS direction:** none directly; this is pure beta-instrumentation.
- **More capable or more passive:** the owner gets real numbers instead of "vibes" for an in-person test — directly serves north star 3 via measurement that can be tuned.
- **Machine:** no machine choice involved (pure Swift package + iOS app code).

## Tests-first (CaptionCore, `swift test --package-path Packages/CaptionCore`)

New `Packages/CaptionCore/Tests/CaptionCoreTests/EarDelayTrackerTests.swift`, all against the pure `EarDelayTracker` with literal `Double`s as the fake clock (no real `AVSpeechSynthesizer` needed — "fake voice" means synthetic `voiceStarted` events, not a mock of Apple's class):

1. **Happy path** — `phraseReady` → `translationReady` → `voiceStarted` for one line yields a `Sample` with `translateDelay = translationReady - phraseReady`, `voiceStartDelay = voiceStarted - phraseReady`, `behindBy = 0` (no backlog, it's the latest phrase).
2. **A phrase rewritten after it was spoken (translation re-issued): one line, not two** — two `phraseReady` calls for the same `lineID` (early + final phrase split, #238) keep the FIRST call's anchor; a second `translationReady` call for the same line is a no-op; `voiceStarted` for that line returns exactly one `Sample`, and a repeat call returns `nil`.
3. **A translation that never arrives** — `phraseReady` with no `translationReady`, then `voiceStarted`: returns `nil`, no crash, nothing recorded.
4. **A voice cut off by the next line** — line A never gets `voiceStarted`; line B (later `lineID`) runs its full sequence independently and produces a correct `Sample` unaffected by A's dangling entry.
5. **No negative or endless delays** — construct out-of-order timestamps where naive subtraction would go negative (e.g. `translationReady` before `phraseReady`); assert all three fields clamp to `0`, never negative.
6. **A 2-hour session: memory stays bounded** — call `phraseReady` for `EarDelayTracker.maxPending + 50` distinct line ids with no completion; assert pending storage never exceeds `maxPending` (via `@testable import CaptionCore`, matching this file's existing internal-access pattern).
7. **A clock change during the session** — feed a non-monotonic timestamp sequence; assert no crash and all derived values stay finite and non-negative (the pure type can't fix a bad clock, but must not produce garbage).
8. **Two speakers overlapping on iPad face to face** — not a new test here: already structurally unreachable, since `EarPhrases.isSpoken` excludes `lane != nil` lines (`EarTranslation.swift:101`) and `EarCenter.take` only ever calls `delayTracker.phraseReady` for phrases `EarPhrases.take` actually emits. I will note this as "covered by existing exclusion" rather than duplicate it.
9. **Count a line spoken twice** — two different line ids each complete the full sequence; assert two independent `Sample`s (not deduplicated by identical values).
10. **Misuse not in the ticket's list — a person's mistakes**: `voiceStarted` called for a `lineID` that was never registered via `phraseReady` → returns `nil`, no crash.
11. **Misuse — concurrency/out-of-order**: interleave `phraseReady`/`translationReady`/`voiceStarted` across three line ids in a shuffled order; each resolves independently and correctly.
12. **Misuse — malformed input**: `NaN`/infinite timestamps don't crash the pure arithmetic (Swift `Double` propagates `NaN`, it doesn't trap); downstream `PercentileHistogram.add` already drops non-finite values (existing guard, `BetaFeedback.swift:92`) — add one test confirming a `NaN` sample doesn't corrupt the histogram's `count`/percentiles.
13. **A phrase's own `EarPhrases.Phrase.readyAt` equals the `now` passed to `take()`** (locks the new field's contract) — added to existing `EarTranslationTests.swift`.
