**Column meanings:**
- **Battery drop (%):** difference between start charge and end charge, as a percentage. Start must be 80-90%.
- **Battery drop (% per hour):** scaled to a 1-hour baseline for cross-device comparison (if 60 min gives 8% drop, this is 8%).

## Component breakdown: CPU-feature delta runs

Since Instruments' Power template cannot distinguish diarization CPU from caption-engine CPU from ambient-sound-detection CPU (all are in one CPU bucket), measure app-feature costs via controlled delta runs: for each CPU-bound feature, run a 60-minute session with that feature disabled and compare battery drop to the baseline (all features enabled).

**Delta-run procedure:**

For the same phone + engine pair (e.g., iPhone 17 Pro + Parakeet):
1. Run the baseline with all features enabled (record as "Baseline" in the Component costs row).
2. Run with diarization disabled: open the developer panel, disable Sortformer before starting the session. Record the battery drop; the delta from baseline is attributed to diarization.
3. Run with ambient-sound detection disabled: open the developer panel, disable ambient detection before starting. Record the battery drop; the delta is attributed to sound labels.
4. The caption-engine cost is the baseline minus the sum of diarization and ambient-sound deltas (or, if one dominates, the leftover after the largest contributor is accounted for).

All three runs (baseline + 2 deltas) must pass the invalidation checklist for the same phone + engine pair. Record all three in a "Component deltas" sub-table within the main table section, showing: baseline battery drop, diarization-disabled drop (and delta), ambient-detection-disabled drop (and delta), and computed caption-engine cost.

Reason: never a fabricated number. The Power template's Energy Impact Categories are system-level; app features map to custom deltas, not pre-computed categories.

## Invalidation checklist

The following conditions invalidate a run. Tick off each before recording the numbers.

- [ ] **Charger:** phone was not plugged into any power source during the 60-minute session.
- [ ] **Low Power Mode:** disabled (not `ON`). Check Settings › Battery.
- [ ] **Thermal state:** record the highest thermal state observed during the run in the table's "Thermal state" column. If `.serious` or `.critical` appeared, note when it occurred (timestamp). Do not discard the run — C4's pass criterion measures whether thermal stays `.serious`-free; skipping hot runs hides exactly the failure C4 evaluates.
- [ ] **Matched start charge:** for the same phone (SE or 17 Pro), the Parakeet run and Apple run must start within 2 percentage points of each other (e.g., both at 84%, not one at 80% and one at 90%). This ensures the engine comparison is not confounded by starting charge level.
- [ ] **Matched room temperature:** Record the ambient room temperature (or phone start temperature via Settings › Battery › Health) at the beginning of each run. For the same phone, the Parakeet and Apple runs (which happen at different times) must have room temperatures within 2 °C of each other. This safeguards against confounding thermal drift across the engine pair. Record the temperature for each run in the table's "Notes" column.
- [ ] **Screen:** screen never locked, never dimmed. Full brightness throughout.
- [ ] **Same device, same engine:** each row of the table is one unique phone + engine pair. The same engine on SE and 17 Pro are two separate runs.

**Candidate fix patterns to explore:**

This section will be filled in after real battery numbers exist, with the actual biggest cost component and 1-3 candidate fixes. The following patterns are already documented in prior work and may be relevant:

- **Diarization cadence** (ADR 0015): Sortformer can run every N buffers instead of every one, or skip during silence. Latency cost likely: low (diarization is best-effort).
- **Decode hop / AdaptiveHop** (ADR 0015): Parakeet codec hop size affects latency-battery trade-off. Longer hops = fewer encoder passes = lower power, but higher latency. Current design: adaptive hop (0.5–1.5 s, doubled at `.serious` thermal state).

## Notes

- The app's beta report captures per-conversation battery drop; this doc's lab measurement captures 60 continuous minutes with both engines, same controlled conditions. Both are valid; they measure different things (one controlled, one real-world). The comparison section bridges them.
- C4 pass criteria (ADR 0025): battery drop ≤ 1.3 × Apple's, and ≤ 15% per hour; thermal never `.serious` (`.serious` with adaptive hop doubling: Gil decides). These criteria drive the optimization roadmap.
- For the SE class phone, the LCD panel means dark theme has no power-saving advantage (unlike the 17 Pro's OLED). Use the same theme as the 17 Pro run for a fair comparison, or note the theme difference in the "Notes" column if it changes between runs.
